## 5. Today's work: the consensus shadow had been copying itself for nine days, and the cause was one write

BACKLOG **248** (2026-09-24) and **250** (2026-09-25) described the same symptom — `grades.jsonl` growing without
adding information, "graded 477,809", then 646,265, then **1,511,157** for about eleven thousand real rows — and
neither had a cause. It is one file.

**`data/polymarket-consensus/state.json` does not parse:** `JSONDecodeError: Invalid control character at char
105,906,176` of 172 MB. The old save was `json.dump(state, open(STATE, 'w'))`, which truncates before it refills,
and the task's `ExecutionTimeLimit PT45M` landed inside that write on 2026-09-21T10:00Z. `load_json` catches every
exception and returns its default, so from that instant every hourly pass got an **empty** state:

| cursor | consequence | visible as |
|---|---|---|
| `recent` empty | every trade in the 72 h API window counts as new | `12,9xx new trades` every hour for nine days |
| `signaled` empty | the same conditionIds re-emit signals | 28,517 signal rows for 14,385 distinct |
| `graded` empty | every settled signal is re-graded and re-appended | 1,511,157 grade rows for 11,073 distinct |

**And the reason it never healed is the other half of the same clamp.** With `graded` empty there were thousands of
signals to fetch at ~0.15 s plus a network call each, so **not one pass since 2026-09-21T14:00Z reached the final
state write** — 213 hourly passes, not a single `graded N signals` line, and the 06:55Z pass still alive at 11:05Z,
four hours into an hourly job. The cursor could not advance because the pass could not finish, and the pass could
not finish because the cursor had not advanced. Neither half is a defect alone; together they are self-perpetuating,
which is why two sessions described it and neither named it.

**Fixed in four places**, all in `scripts/polymarket_consensus.py`:

1. `save_state` writes `state.json.tmp` then `os.replace`s it. A kill can no longer corrupt the file.
2. `load_state` no longer accepts an empty state silently: if `state.json` is missing or unreadable it says so in
   the run log and calls the new `rebuild_state()`, which reconstructs all three cursors **from the journals** —
   the journals are the record; the state file is only a cursor over them.
3. Grading takes a **20-minute wall-clock budget** so the pass always reaches the save inside the 45-minute task
   limit. A bounded pass that saves beats a complete pass that is killed.
4. Grade rows now carry `conditionId`, so the graded index rebuilds exactly instead of by joining on
   `(ts, title, outcome)`.

**The journals are de-duplicated by a re-runnable `repair` subcommand, not by hand:** trades **3,871,169 →
1,702,953** distinct (2,405 MB → 1,048 MB), signals **28,517 → 14,385**, grades **1,511,157 → 11,073** (482 MB →
3.7 MB); state rebuilt with 14,385 signalled, 9,904 graded, 180,610 trades in the 72 h window. The de-duplicated
grade count reproduces BACKLOG 248's independent hand count to **32 rows** and its Brier to four decimals
(**0.1008**) — which is what proves the key `(title, kalshi_market, ts)` is the right one.

One number in there will trip a careful reader, so it is stated rather than glossed: **11,073 distinct grade rows
are 9,904 distinct graded signals.** The gap is 1,169 rows where the same `(conditionId, outcome)` was graded
against **two different Kalshi markets** — the old matcher's and the new one's — which is precisely the class the
09-19 amendment voided. The row key is the right one for reading the Kalshi leg (one row per match is what you
want) and over-counts for the Polymarket leg; the grading cursor keys on the signal instead, which is why
`rebuild_state` reports the smaller figure. Both numbers are correct and they are not the same question.

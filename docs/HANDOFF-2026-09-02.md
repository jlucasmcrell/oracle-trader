## 3. What is proven (mechanics)

All verified on the Kalshi demo exchange today, with real order round-trips:

- Order placement: taker (crosses) and maker (post_only, rests inside the spread), with
  server-side expiration; amend (reprice) and cancel; **per-shard order groups** (Kalshi runs
  separate matching engines per `exchange_index`; a group only exists on the shard it was
  created on — the adapter keeps one per shard and retries once on `order_group_not_found`).
- Fill reconciliation (placement fill, reconcile loop, amend fills, VWAP), promotion to open
  trades, settlement from the venue, P&L booked to the cent (verified against balance).
- Batch order books chunked at 50 tickers (the endpoint caps around 100; a single overflowing
  request silently produced zero books and zero signals for a whole horizon — fixed and
  surfaced as an error).
- Polymarket US `sellPosition` now converts the YES-leg execution price for NO exits (bug found
  by an external review 2026-09-02; before the fix a NO exit booked the YES price).
- Settlement units: Kalshi `revenue` is integer cents, `fee_cost` is dollars despite the
  missing suffix. Polymarket US settlement comes from `/book` (state + `settlementPx`), not
  `/settlement` (404s); fractional settlements are booked as MKT-at-price.
- Risk rails: daily-loss kill switch; mode-flip and demo-toggle guards while holding; orphan
  sweep (cancels untracked `ot-*` resting orders in live mode); ledger write-then-rename;
  decrypt failures keep ciphertext instead of destroying keys.
- Grading: every settled trade now records **net cents per contract after the fee actually
  charged**, with per-event and per-day sums; status exposes an event-clustered 95% interval.
  This is the base-rate-proof number (see §5). It populates from the first settlement on the
  current build.
- Fee model: per-series `fee_type` is read from `/series`; maker fee is zero on plain
  `quadratic` series and `0.07 × multiplier` on `quadratic_with_maker_fees` series (Kalshi bills
  makers on e.g. KXMLB/NBA/NFL since 2026-08-19; the exact maker coefficient is unverified —
  the current value overstates maker cost, the safe direction).

## 5. The evidence discipline (why win rate lied to us)

The app ran 34-0, then 36-0, on paper. That was the ~90% favorite base rate, not skill: buying
at 91¢ and winning 88.5% of the time loses 2.5¢ a contract. Every strategy decision now
follows these rules, and they are the most valuable thing in this repo:

1. **Point-in-time replay on public data first.** Use the entry price available at the
   decision time (1-minute candles, or the collector's live book), never the terminal price.
   Kalshi's 1-minute candles are retained ~2 weeks; hourly candles longer.
2. **Fees in, always.** Kalshi taker fee `ceil(0.07 × mult × C × p(1−p) × 100)/100` per order.
   None of the seven public bots reviewed today model fees; every profit claim in them is gross.
3. **Cluster.** Same-event rows (a prop ladder, a strike ladder, all coins in one 15-minute
   window) are one draw. Report event- and day-clustered intervals.
4. **Correct for the grid.** A rule chosen from N cells is reported with a Bonferroni
   interval (z = 3.02 for 20 cells, 2.39 for 3).
5. **Baseline decomposition.** Report what the opposite side / always-YES / always-NO would
   have made in the same band, so "beat the market" is separated from "held the winning side."
6. **Pre-register before forward data exists.** `docs/PREREGISTERED-*.md` fix the rule and
   the pass criteria; amendments are dated and restart scoring. Nothing enters the app until a
   gate passes; passing authorizes tiny-live ($1–2/contract, capped), never size.
7. **A high win rate is not profit; a positive headline carried by one correlated family is
   noise.**

Tools that embody this: `scratchpad/pit4.mjs` (62-day stratified replay),
`scratchpad/pit15.mjs` (15-minute windows), `scripts/btc-gate.mjs`, `scripts/hunch-gate.mjs`.

## 9. Non-negotiables

- Never fire a real-money order from an ad-hoc script; the app trading under a config the
  operator armed is the only path. The `liveArmed` click is the operator's.
- Never trade the Polymarket.com CLOB; never automate Kalshi Perpetuals.
- Never paste keys into chat or logs; all credentials stay `enc:` ciphertext in config.
- Never treat a paper or demo win streak as evidence. Never relax a pre-registered gate after
  seeing data. Never let a cached field (closeTime, resolution) be the sole gate on settlement.
- Never let a `.catch(() => [])` on a data fetch silently become "nothing to do"; surface
  emptiness as an error (this class of bug hid three real failures today).

## 10. How to add a strategy (the only way that has worked)

1. State where the money comes from without out-forecasting the crowd (liquidity, discrepancy,
   independent truth source, speed). If it is a forecast, expect it to fail.
2. Screen it offline on public data with `pit4.mjs`-style point-in-time replay: fees, event and
   day clustering, Bonferroni for the grid, baseline decomposition. Most candidates die here in
   under an hour; that is the point.
3. If a cell survives, write `docs/PREREGISTERED-<name>.md` before any forward data exists.
4. Add the data the forward test needs to the collector; write a gate script that prints
   PASS/FAIL.
5. On PASS: minimal implementation (feed, carve-out, sub-loop, per-observation logging), then
   tiny-live with a positive day-clustered CI over ≥100 live events before any size.
6. Size doubles only while the trailing-30-day clustered interval stays positive; halves the
   moment it crosses zero; never exceed 2% of touch depth.
